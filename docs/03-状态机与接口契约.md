# 03 状态机与接口契约（施工规格文档）

- 本文档是后端写状态机代码与前端按钮/页面逻辑的直接依据：状态与动作是代码枚举（显式状态机），审批节点配置表只解决"谁审、会签吗、多久内必须处理、能否退回"，**不产生新的业务状态**。
- 状态机唯一入口：`RecordTransitionService.fire(recordId, action, operator, dto)`，在一个事务内完成"取分布式锁 → 校验角色与前置条件 → 更新状态/写审批任务/写评分单/写快照/写日志"。
- 关联：[01-技术方案.md](./01-技术方案.md) §5.2 锁、§6.0 三层结构；[02-数据模型.md](./02-数据模型.md)；[04-决策规则与验证.md](./04-决策规则与验证.md)。

## 1. 考评单主状态机

### 1.1 状态清单（11 个，与 `perf_record.status` 一一对应）

| # | 状态码 | 中文 | 含义 | 当前节点 |
|---|---|---|---|---|
| 1 | `DRAFT` | 草稿 | 员工/HR 初始化后，员工填报实际值、自评分、上传材料中 | 无 |
| 2 | `SUBMITTED` | 已提交，待部门评审 | 自评提交成功，N1_DEPT 任务已生成 | N1_DEPT |
| 3 | `RETURNED` | 退回修改 | 被某节点退回，在员工侧重新填报 | 无 |
|4 | `DEPT_PASSED` | 部门评审通过，待 HR 复核 | 主管打分完成，快照 AFTER_DEPT 已生成，N2_HR 任务已生成 | N2_HR |
| 5 | `HR_PASSED` | HR 复核通过，待终审 | 人工结论可以开始保存，N3_FINAL 任务已生成 | N3_FINAL |
| 6 | `FINAL_PASSED` | 终审通过，待员工确认 | 人工结论已生效，finalized_at 设置（申诉时限起算） | 无 |
| 7 | `CONFIRMED` | 已确认结果 | 员工已知悉确认，可关闭或转改进计划 | 无 |
| 8 | `APPEALING` | 申诉中 | 申诉单已立案，主单冻结（不能改数据，只能处理申诉） | APPEAL_REVIEW |
| 9 | `IMPROVING` | 改进中 | 改进计划执行中，主单不可再评分 | 无 |
| 10 | `CLOSED` | 已办结 | 终态：归档，只读 | 无 |
| 11 | `CANCELLED` | 已作废 | 终态：行政作废（如错误初始化），只读 | 无 |

### 1.2 动作清单（21 个，与操作日志 action 一致）

| 动作码 | 中文 | 摘要说明 |
|---|---|---|
| `SAVE_DRAFT` | 保存草稿 | 保存实际值/自评分/材料，不流转 |
| `SUBMIT` | 提交自评 | 校验完整 → 生成部门审批任务 → 引擎出快照 |
| `RESTORE_DRAFT` | 还原草稿 | 目标确认后自动生成草稿单时的初始化动作（系统动作） |
| `DEPT_APPROVE` | 部门通过 | 主管评分通过，生成 HR 任务，引擎正式快照 |
| `DEPT_RETURN` | 部门退回 | 附理由打回员工 |
| `RESUBMIT` | 修改后重新提交 | 处理完退回意见，回到部门评审 |
| `HR_APPROVE` | HR 复核通过 | 生成终审任务 |
| `HR_RETURN` | HR 退回 | 可配退回到部门或员工 |
| `FINAL_APPROVE` | 终审通过 | 必须先有有效人工结论 → 发布结果 |
| `FINAL_RETURN` | 终审退回 | 附理由，按节点配置决定落点 |
| `ADJUST_CONCLUSION` | 调整建议作出结论 | 基于快照改分数/等级，理由必填，状态可不变 |
| `ADOPT_CONCLUSION` | 直接采纳建议 | 不改数，is_adjusted=0 |
| `CONFIRM_RESULT` | 确认结果 | 员工知悉终审结果 |
| `APPEAL` | 发起申诉 | 时限内、无未结案申诉 |
| `WITHDRAW_APPEAL` | 撤回申诉 | 复核结论作出前可撤回 |
| `APPEAL_SUSTAIN` | 裁定申诉成立 | 主单回退到 HR_PASSED 重走终审 |
| `APPEAL_REJECT` | 裁定驳回 | 回申诉前状态 |
| `CREATE_PLAN` | 发起改进计划 | 低等级或人工发起 |
| `COMPLETE_PLAN` | 验证完成改进 | 全部任务完成 → CLOSED |
| `CANCEL_PLAN` | 取消改进计划 | 回到 CONFIRMED 待关闭 |
| `CLOSE` | 归档关闭 | 无未决事项后办结 |
| `CANCEL` | 作废考评单 | 仅 ADMIN，仅在 DRAFT/RETURNED |

### 1.4 必须拒绝的非法转换（返回 40900，前端按钮应隐藏，后端必须独立校验）

1. **跳节点**：DRAFT 直接到 HR_PASSED/FINAL_PASSED；SUBMITTED 上直接 HR_APPROVE/FINAL_APPROVE；DEPT_PASSED 再 DEPT_APPROVE。
2. **逆向审批**：HR_PASSED 回到部门审批；FINAL_PASSED/`CONFIRMED` 后改评分（改分只能先申诉且申诉成立）。
3. **终态操作**：CLOSED、CANCELLED 上执行除查询外的任何动作。
4. **无结论终审**：HR_PASSED 下没有 perf_manual_conclusion 行就 FINAL_APPROVE。
5. **角色非法**：员工审批自己/他人的单；非任务 assignee 点通过；部门负责人处理非本部门子树的单（即使手拼请求，返回 40301）。
6. **草稿态申诉/确认**：DRAFT、SUBMITTED、RETURNED 下发起 APPEAL、CONFIRM_RESULT。
7. **超时申诉**：超过 appeal.limit-days 发起申诉；同一单重复发起（已有未结案申诉）。
8. **退回态直接推进**：RETURNED 上调用 HR_APPROVE/FINAL_APPROVE（必须 RESUBMIT）。
9. **会签未齐**：ALL 节点尚有 PENDING  assignee 时推进状态。
10. **申诉期改数据**：APPEALING 状态修改 record_item 分数/实际值。
11. **计划未完成办结**：IMPROVING 下仍有 TODO/OVERDUE 任务时 COMPLETE_PLAN。
12. **已提交后作废**：SUBMITTED 及之后状态调 CANCEL（仅 DRAFT/RETURNED 允许）。
13. **锁冲突**：并发审批同一单，未抢到锁的请求返回 40901，不允许后写覆盖先写。
14. **时限外提交/评审**：超过各阶段截止时间的动作（HR 代提交豁免员工时限，节点超期不锁死审批，只计入催办/看板逾期）。

### 1.5 节点"跳过"与退回落点

- 若某作用域下节点配置被停用（enabled=0），提交时**按 node_seq 找下一个启用节点**生成任务，被跳过节点写一行 appr_task(status=SKIPPED)，保证轨迹完整。
- 退回落点由该节点 `return_to_node` 决定：NULL=退回员工（RETURNED，重走全链）；N1_DEPT=退回主管（SUBMITTED，员工数据冻结不变）。
- 状态码始终只有 §1.1 的 11 个，"跳到哪"是任务编排结果而非新增状态。

## 2. 次要状态机

### 2.1 周期 perf_cycle.status

| 当前 | 动作 | 角色 | 前置 | 次态 |
|---|---|---|---|---|
| DRAFT | PUBLISH | HR | 至少 1 套 PUBLISHED 方案且权重校验通过；四类截止时间完整 | PUBLISHED |
| PUBLISHED | FINISH | HR | 所有考评单 ∈ {CLOSED,CANCELLED}（未完成时需 ack=true 并记录原因） | FINISHED |
| FINISHED | ARCHIVE | ADMIN | 已结束周期，快照/日志完整 | ARCHIVED |
| any | EDIT_BASIC | HR/ADMIN | DRAFT 可任意改；PUBLISHED 只准改截止时间（延长），并写 log | 不变 |

### 2.2 目标 perf_target.status

| 当前 | 动作 | 角色 | 前置 | 次态 |
|---|---|---|---|---|
| DRAFT | DISTRIBUTE | DEPT_MANAGER/HR | 明细至少 1 条；target_required 项有目标值；权重合计与方案一致 | DISTRIBUTED |
| DISTRIBUTED | CONFIRM | 员工本人 | — | CONFIRMED（同事务生成 DRAFT 考评单） |
| DISTRIBUTED | DISPUTE | 员工本人 | dispute_reason ≥ 5 字 | DISPUTED |
| DISPUTED | REVISE | 经理/HR | 至少修改过一条明细（updated_at 变化） | DRAFT |
| DRAFT/DISTRIBUTED | EDIT_ITEMS | 经理/HR | 员工确认后（CONFIRMED）锁死；确认后调整需走"周期内目标变更"——仅备注与实际值口径字段可改并写 log（默认规则，见 01 Q6） | 不变/DISPUTED |

### 2.3 申诉 perf_appeal.status

`SUBMITTED` →（HR 受理）`REVIEWING` → `SUSTAINED` / `REJECTED`；SUBMITTED/REVIEWING →（员工）`WITHDRAWN`。终态三选一，不可再变。

### 2.4 改进计划

plan：`IN_PROGRESS` → `COMPLETED`（所有任务 DONE）/ `CANCELLED`。
task：`TODO` → `OVERDUE`（定时任务，每日 00:10）；`TODO/OVERDUE` → `DONE`（员工自评完成 + 经理验证，verify_comment）。

### 2.5 审批任务 appr_task.status

`PENDING` → `APPROVED` / `RETURNED` / `REJECTED`；节点跳过时直接生成 `SKIPPED`。状态机推进时以"同 biz 同 node_seq 全部任务的聚合结果"为判定（ANY 一个 APPROVED 即过；ALL 需全部 APPROVED）。

## 3. 接口总览与通用约定

### 3.1 基本信息

- Base URL：`/api/v1`；Knife4j 地址开发期 `http://localhost:8080/doc.html`。
- 除登录接口外，请求头必须带：`Authorization: Bearer {accessToken}`。
- 请求/响应仅 UTF-8 JSON；文件上传为 `multipart/form-data`；时间传 ISO（`2026-12-20T18:00:00`）或 `yyyy-MM-dd HH:mm:ss`，后端统一 `@JsonFormat(pattern="yyyy-MM-dd HH:mm:ss")`。
- HTTP 状态码：业务 JSON 接口统一返回 **HTTP 200**，成败看响应体 `code`（文件流下载除外，失败返回 JSON 错误体）。
- 权限列写法：角色码集合；"本人/子树/全部"的数据范围在服务端按角色强制。
- 所有写接口都写 sys_operation_log（`@OpLog` 注解）。

### 3.2 统一响应体

```json
{
  "code": 0,
  "message": "ok",
  "data": { },
  "traceId": "a1b2c3d4e5f6"
}
```

- `code=0` 成功；非 0 见 §3.5；`message` 可直接展示给用户的中文信息；`traceId` 用于排查。
- 分页 data 结构：

```json
{ "total": 128, "pageNum": 1, "pageSize": 10, "list": [ ] }
```

### 3.3 分页/排序入参（所有 GET 列表接口统一）

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| pageNum | int | 1 | 页码，从 1 起 |
| pageSize | int | 10 | 每页条数，最大 100 |
| orderBy | string | 各接口默认 | 白名单字段（如 created_at、finalized_at），禁止透传 SQL |
| orderDirection | string | desc | asc/desc |

### 3.4 鉴权相关响应约定

- 40100：无/错 token；40101：过期（前端拦截后用 refreshToken 换新，最多重试 1 次）；40102：被踢下线；40300：角色不足；40301：数据越权。
- 登录连续失败/频率超限 → 42900。

### 3.5 错误码规范（全局枚举，禁止各模块自定义数字）

| code | 含义 | 典型触发 |
|---|---|---|
| 0 | 成功 | — |
| 40000 | 请求参数通用错误 | 内容类型错、body 格式错 |
| 40001 | 参数校验失败 | `@Valid` 失败，data 里返回字段级错误 |
| 40100 | 未登录/令牌无效 | 缺头、签名错、会话不存在 |
| 40101 | 令牌过期 | accessToken 过期 |
| 40102 | 会话已被踢出 | 单点登录顶号 |
| 40300 | 无权限（角色不足） | 员工调 HR 接口 |
| 40301 | 数据越权 | 访问非本人/非本子树数据 |
| 40400 | 资源不存在 | id 查不到或已删 |
| 40900 | 状态冲突（非法状态转换） | §1.4 全部场景 |
| 40901 | 单据处理中（审批锁冲突） | 未抢到 Redis 锁 |
| 40902 | 唯一约束冲突 | 重复编码、重复发起等 |
| 42201 | 业务规则校验失败 | 权重≠100、分档不连续、时限判断等 |
| 42900 | 请求过频/登录锁定 | 登录失败锁定、AI 限流 |
| 50000 | 服务器内部错误 | 未预期异常（带 traceId） |
| 50300 | 依赖不可用 | MySQL/Redis 连不上 |
| 50301 | 智能助手未启用 | `ai.agent.enabled=false` |

### 3.6 Agent 接口的降级响应（统一形态，三能力一致）

- 开关关闭：`code=50301,message="智能助手未启用"`，data 为 null。
- 运行期故障（**超时 8 秒 / 额度用尽 / 断网或未配 Key**）：**HTTP 200、code=0、data 中带降级标记**，业务前端不报错、只在结果区顶部显示"解释服务暂不可用"：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "callLogId": 8821,
    "degraded": true,
    "failReason": "TIMEOUT",
    "retrievalMode": "BM25",
    "content": "（规则引擎模板生成的中文文案，含真实分数、因子贡献、依据列表）",
    "draft": null,
    "report": null,
    "citations": [ ]
  },
  "traceId": "..."
}
```

正常时 `degraded=false`、`failReason=null`，结构化字段（draft/report/evaluation）按接口填。每次调用必有 callLogId 对应 `agent_call_log` 一行。

**③ POST `/agent/capabilities/inspection/run`（C3 异常巡检）**

- 权限：HR_SPECIALIST、EXECUTIVE
- 入参：`{ cycleId, anomalyTypes?: ["TARGET_DEVIATION","MATERIAL_MISSING","SCORE_GAP","APPEAL_TIMEOUT"] }`（缺省四类全扫）
- 扫描口径（纯查询，阈值见 01 §6.2 C3）：
  - TARGET_DEVIATION：目标值与同岗位中位数偏离 >30% 或与本人上一周期差异 >±30%；
  - MATERIAL_MISSING：已提交（SUBMITTED 及之后）单据中 target_required=1 指标无有效材料；
  - SCORE_GAP：self_total 与 manager_total 差 > HC_SCORE_GAP（默认 25）；
  - APPEAL_TIMEOUT：appeal 处于 SUBMITTED 超 3 个工作日未受理。
- 返回 data：

## 5. 前端对接要点（配合接口）

1. 考评单详情接口返回 `availableActions`：按钮只渲染数组内动作；所有动作统一 POST `/records/{id}/actions`。
2. 40901 锁冲突：弹"他人正在处理"，2 秒后自动刷新详情，不做排队。
3. 40101：Axios 单次自动 refresh 重试；40102：清登录态并提示"已在其他设备登录"。
4. 退回意见、申诉理由、调整结论理由等必填文案由前端按本文件字数限制先校验，后端必须再校验。
5. Agent 三个能力页：结果区分"草案区"和"确认落库按钮"；草案不落库；`degraded=true` 时顶部黄条"解释服务暂不可用"，内容仍展示（模板数据为真实计算值）。
6. ECharts 三图直接使用 dashboard 返回结构；卡片用 overview 与 approval statistics。
