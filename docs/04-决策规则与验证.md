# 04 决策规则与验证（施工规格文档）

- 引擎定位：**纯 Java 确定性规则引擎**（无模型、无浮点、零外部依赖），是 Agent 三层结构中的第二层（01 §6.0），可被状态机正式调用（写快照），也可被 Agent 以 dry-run 方式调用（只返回，不落库）。
- 同样输入 + 同样规则版本 → 必产同样输出（可复算性）；规则全部来自 02 文档三张配置表（`perf_factor_config` / `perf_hard_constraint` / `perf_grade_band`），规则随方案带版本号 `rule_version`。
- 引擎对业务表只读 + 只写 `perf_recommendation_snapshot`；分数最终采信人工结论表。LLM 在任何情况下都不能替代规则算分（降级时 Agent 用引擎结果套模板）。
- 关联：[01 §6.0](./01-技术方案.md) 三层结构、[02 §3/§6](./02-数据模型.md) 规则表与快照表、[03 §4.10](./03-状态机与接口契约.md) 引擎接口。

## 1. 数据流与计算总览

```
record_item（目标值/实际值/各阶段评分）
  + perf_record.aux_data（考勤/纪律/培训/协作/历史等非指标取数字段，结构见 §2.7）
  + 历史 perf_record（最近两期 final_total）
        │
        ▼
① 因子计算层：六个 FactorCalculator，每个输出 {score, available, dataPoints, evidence}
        │
        ▼
② 硬约束检查层：5 条硬约束，输出 {hit, actual, threshold, actionType, ceilingGrade, evidence}
        │
        ▼
③ 总分聚合 + 等级分档（先算 raw grade，再应用等级封顶）
        │
        ▼
④ 置信度与人工判定（缺失率/评分差/历史覆盖 → needManualConfirm + reasons
        │
        ▼
⑤ 决策树（§4）：固定三(层)判定顺序，产出最终输出（§5）
        │
        ▼
perf_recommendation_snapshot（不可变；dry-run 不写）
```

## 2. 六个决策因子

> 取值域统一 0–100；中间过程一律 `BigDecimal`，中间值保留 4 位小数，最终因子分四舍五入（HALF_UP）保留 2 位；比率用百分数值（80.00=80%）。
> 每个因子的当前评价阶段决定取哪个阶段的分：AFTER_SELF 用自评分；AFTER_DEPT 用部门分（hr_score 为空则 manager_score）；MANUAL_RERUN 同 AFTER_DEPT 口径。

### 2.1 F1 量化指标达成率（权重默认 40）

| 项 | 说明 |
|---|---|
| 数据 | `category=QUANTITATIVE` 且 factor_code=F1 的 record_item |
| 输入 | target_value_snapshot、actual_value、scoring_rule.direction |
| 正向达成率 | `rate_i = 100 × actual / target`（target=0 或实际空 → 该数据点缺失） |
| 反向指标 | `rate_i = clamp(200 − 100 × actual / target, 0, 120)`（越低越好，如差错率） |
| 达成率封顶 | rate 展示封顶 120.00（`rateCap`），**指标得分 s_i = clamp(rate_i, 0, 100)**（超额不加分到 100 以上，防止单指标拉动总分失真） |
| 因子分 | `F1 = round2( Σ(wᵢ × sᵢ) / Σwᵢ )`，wᵢ 取 item 权重快照，仅对有数据项累加 |
| 可用判定 | 有数据项占比 < 50% → F1 不可用（score=null，进入 §3.4 缺失处理） |
| 依据 | 每项一行：指标名/target/actual/rate/s/公式 |

### 2.2 F2 重点工作完成质量（权重默认 20）

| 项 | 说明 |
|---|---|
| 数据 | factor_code=F2 的 record_item（多为 QUALITATIVE：重点项目、专项任务） |
| 因子分 | `F2 = round2( Σ(wᵢ × 阶段分ᵢ) / Σwᵢ )`，阶段分：AFTER_SELF 取 self_score，之后取 hr_score 优先、否则 manager_score |
| 特殊 | 无 actual_value 不算缺失（定性指标），但**阶段分缺失**算缺失数据点 |
| 依据 | 任务名/阶段分/评审人评语（截 50 字） |

### 2.3 F3 价值观与行为规范（权重默认 15）

| 项 | 说明 |
|---|---|
| 数据 | factor_code=F3 的定性项（责任心/合规/团队协作等行为项） |
| 因子分 | 同 F2 加权平均；AFTER_SELF 阶段只有自评时因子分照常出，但一致性分量按无主管分处理（§6.2） |
| 依据 | 行为项名称与打分；标识"当前仅自评口径" |

### 2.4 F4 出勤与合规（权重默认 10）

| 项 | 说明 |
|---|---|
| 数据 | `perf_record.aux_data`：`attendanceRate`（百分数值，如 76.00）、`disciplineEvents`（次数，默认 0）、`disciplineLevel`（NONE/WARNING/DEMERIT/MAJOR，默认 NONE） |
| 因子分 | `F4 = round2( clamp(attendanceRate − disciplineEvents × p, 0, 100) )`，p 取 `perf_factor_config.calc_params.deductPerEvent`（默认 10 分/次） |
| 边界 | attendanceRate 空 → F4 不可用；disciplineLevel 用于硬约束 HC_DISCIPLINE_VETO，不重复扣分（次数扣分与等级约束并行） |
| 依据 | 出勤率、违纪次数与等级、扣分公式 |

### 2.5 F5 能力成长（权重默认 5）

| 项 | 说明 |
|---|---|
| 数据 | aux_data：`trainingHours`、`requiredTrainingHours`（calc_params.requiredHours 默认 24）、`abilityTestAvg`（0–100，可空） |
| 学时达成 | `r = clamp(trainingHours / requiredTrainingHours, 0, 1)` |
| 因子分 | 齐全：`F5 = round2( r×60 + clamp(abilityTestAvg,0,100)×0.4 )`；缺测评：`F5 = round2(r×100)`（该数据点计缺失，完整度打折）；两者皆缺 → F5 不可用 |
| 依据 | 学时/要求学时、测评均分、采用公式分支 |

### 2.6 F6 协作评价与历史绩效趋势（权重默认 10）

| 项 | 说明 |
|---|---|
| 数据 | aux_data.`peerScore`（0–100，可空）；历史数据：该员工最近两期 status=CLOSED 的 perf_record.final_total（不足两期按实有） |
| 趋势分 | `histAvg`=近两期均分（一期则取一期；零期 null）；`trend = histAvg==null ? null : min(100, round2(histAvg + (连续两期上升 ? 2 : 0)))`（上升奖励最多 +2，下降不另扣，因为均值已反映） |
| 因子分 | 两者齐：`F6 = round2(0.5×peerScore + 0.5×trend)`；仅其一：取存在的一方（另一方计缺失）；皆无 → F6 不可用 |
| 新人规则 | 历史 0 期不惩罚：该数据点缺失但完整度计算时历史项权重减半（§6.1） |
| 依据 | 协作分来源、引用周期号与历史分数 |

### 2.7 aux_data 结构（`perf_record.aux_data` JSON，HR/经理维护；员工不可见内部算法字段但可见解释中的取数说明）

```json
{
  "attendanceRate": 76.00,
  "disciplineEvents": 1,
  "disciplineLevel": "DEMERIT",
  "trainingHours": 18,
  "requiredTrainingHours": 24,
  "abilityTestAvg": 82.00,
  "peerScore": 78.00,
  "lastCycleCodes": ["2026-Q2", "2026-Q3"]
}
```

> 该字段随考评单快照一起被复制进 snapshot.evidence 留痕（不复制进 factor_results，证据链走 evidence_list）。历史趋势由引擎实时查历史考评单，并把查到的周期/分数写入依据。

## 3. 硬约束（5 条，对应 `perf_hard_constraint`）

| 约束码 | 名称 | 判定（严格不等号：低于用 <，超限用 >，**临界值不触发**） | threshold 默认 | action_type | 封顶档 |
|---|---|---|---|---|---|
| `HC_DISCIPLINE_VETO` | 重大违纪一票否决 | `aux_data.disciplineLevel ∈ {DEMERIT, MAJOR}` | 无阈值（等级触发） | BOTH（强制人工+封顶） | C |
| `HC_ATTENDANCE` | 出勤不达标封顶 | `attendanceRate < 80.00` | 80.00（PERCENT） | CEILING_GRADE | B |
| `HC_KPI_LOW` | 关键量化指标严重未达 | 存在 F1 指标满足 `wᵢ ≥ 15` 且 `rate_i < 60.00` | 60.00（PERCENT） | CEILING_GRADE | B_PLUS |
| `HC_DATA_MISSING` | 数据缺失超限 | 必填数据点缺失率 > 20.00%（口径见 §6.1）；且 F1 缺失率 > 20% 时不给建议等级 | 20.00（PERCENT） | FORCE_MANUAL（等级标记 MANUAL_REQUIRED 见 §4 L1/L3） | — |
| `HC_SCORE_GAP` | 自评主管评价差距过大 | AFTER_DEPT 起：`abs(self_total − manager_total) > 25.00`；AFTER_SELF 阶段跳过（主管分尚不存在） | 25.00（SCORE） | FORCE_MANUAL | — |

约束聚合规则：

1. 多条封顶同时命中 → 取**最严**（严重度排序 S>A>B_PLUS>B>C>D，取排序最靠前者能得到的最高档；如同时命中 B 和 C 封项，最终 ≤ C）。
2. FORCE_MANUAL 与封顶可叠加：等级照常给（封顶后），但 `need_manual_confirm=true` 且 reasons 全部列出。
3. 每条约束输出是否命中、实际值、阈值、触发动作与证据；**逼近不命中**（差距 ≤ 2 个单位）也要输出 `nearHit=true` 供解释面板黄色提示（不影响结论）。
4. HC_DATA_MISSING 命中时置信度上限 0.500（§6.2）。

## 4. 决策树（3 层，固定顺序；参数全部可配）

```
L0 取数与完整度
   计算每个因子的 available / score；计算 missingRatio（§6.1）
   │
L1 一票否决与封顶（硬约束）
   ├─ disciplineLevel ∈ {DEMERIT, MAJOR}        → ceiling = C， reason += HC_DISCIPLINE_VETO
   ├─ attendanceRate < 80                        → ceiling = min(ceiling, B)
   ├─ 存在 weight≥15 的 F1 指标 rate < 60        → ceiling = min(ceiling, B_PLUS)
   ├─ missingRatio > 20% 或 F1 缺失率 > 20%      → needManual=true, reason += HC_DATA_MISSING
   │                                              （F1 缺失率>20% → grade = MANUAL_REQUIRED，跳过 L2）
   └─ AFTER_DEPT 起且 |self−manager| > 25        → needManual=true, reason += HC_SCORE_GAP
   │
L2 总分与分档
   total = 可用因子加权和 / 可用权重和 × 100   （权重再归一，见 §6.3）
   rawGrade = 分档表匹配（六档，左闭右开；分数先 round1 再入档，见 §4.1）
   grade = ceiling==null ? rawGrade : 较严者(rawGrade, ceiling)
   │
L3 人工判定
   ├─ grade == MANUAL_REQUIRED                  → needManual=true
   ├─ confidence < 0.75（engine.confidence.threshold）→ needManual=true, reason += LOW_CONFIDENCE
   └─ 否则                                      → needManual 维持 L1 结果
   输出 total/grade/confidence/needManual/reasons/factorResults/constraintResults/evidence
```

### 4.1 分档与临界（tie）规则

- 默认六档（表 `perf_grade_band`，可改）：

| 等级 | S | A | B_PLUS | B | C | D |
|---|---|---|---|---|---|---|
| 下限（含） | 95 | 90 | 80 | 70 | 60 | 0 |
| 上限（不含） | 999 | 95 | 90 | 80 | 70 | 60 |

- 入档前总分**先四舍五入保留 1 位小数**（HALF_UP）：79.94 → 79.9 → B；79.95 → 80.0 → B_PLUS；恰 80.00 → B_PLUS（左闭）。
- 硬约束临界值同样"含等号不触发"：出勤 80.00 不触发 HC_ATTENDANCE；rate 恰 60.00 不触发 HC_KPI_LOW；差距恰 25.00 不触发 HC_SCORE_GAP。
- 分档表发布前校验六档连续无缺口/重叠（02 §11 已列应用层约束）。

### 4.2 细调规则（调参指引，均为配置项而非代码常量）

| 想要的效果 | 调哪里 | 取值约束 |
|---|---|---|
| 更看重业绩 | 调 perf_factor_config：F1↑、F3/F6↓ | 启用因子合计=100 |
| 更严的纪律导向 | 启用 HC_DISCIPLINE_VETO + 降 deductPerEvent? 不，提 attendance 阈值到 85 | 0–100 |
| 减少误报"人工确认" | 提高 engine.confidence.threshold（调低到 0.6）、放宽 HC_SCORE_GAP 到 30 | 0.5–0.9 / 10–40 |
| 鼓励超额完成 | scoring_rule.rateCap=120 仍封顶得分 100；若要超额加分，需改为方案级配置 `scoreCap`（演示版不开，保持封顶 100） | — |
| 新人不被历史拖分 | F6 历史缺失权重减半（§6.1），无需调权重 | 固定规则 |

## 6. 缺失、权重归一与置信度

### 6.1 必填数据点与缺失率（总权重 100，与因子权重对齐）

| 数据点 | 点权重 | 缺失判定 |
|---|---|---|
| F1/F2/F3 的每个 record_item | 该 item 权重（三项合计 75：40+20+15） | 定量项 actual 为空；定性项在当前评价阶段无对应阶段分 |
| F4：attendanceRate | 6 | 空 |
| F4：disciplineLevel（无违纪显式给 NONE）/ disciplineEvents | 4 | 空（NONE/0 不算缺失） |
| F5：trainingHours | 3 | 空 |
| F5：abilityTestAvg | 2 | 空（缺测评 F5 走单学时分支，但该点计缺失） |
| F6：peerScore | 5 | 空 |
| F6：历史趋势 | 5 | 0 期历史（新人）按 2.5 计缺失、2.5 豁免；有 1 期即不缺（historyCov=0.5） |

- `missingRatio = 缺失权重之和 / 100`。
- F1 内部缺失率 = F1 缺失项权重 / 40（F1 因子总权重；方案改配时按实际权重）。
- 缺失率参与 HC_DATA_MISSING（>20%）与 confidence 计算。

### 6.2 置信度

```
completeness = 1 − missingRatio                                   （0–1）
consistency  = 主管分存在 ? 1 − min(1, |self−manager| / 50)
                            : 0.80（仅自评阶段的中性值，F3 仅自评时同样用此值）
historyCov   = min(1, 有数据的历史周期数 / 2)（新人按 0.5 起步，不惩罚）
confidence   = round3(0.5×completeness + 0.3×consistency + 0.2×historyCov)
若 HC_DATA_MISSING 命中 → confidence = min(confidence, 0.500)
```

### 6.3 权重再归一（缺因子时总分怎么算）

- 可用因子集合 A（available=true）：`total = round2( Σ_{i∈A}(Fᵢ×wᵢ) / Σ_{i∈A} wᵢ × 100 )`，即把缺失因子权重按比例分给在场因子，每个在场因子输出 weightUsed。
- 若 **F1 不可用或 F1 缺失率 >20%**：不给等级（MANUAL_REQUIRED），total 置 null（前端不展示总分）；其他因子缺失（如 F5）且 missingRatio ≤20%：照常归一给参考总分与等级，但 needManual=true（LOW_CONFIDENCE 或 HC_DATA_MISSING）。
- 再归一只影响总分展示，**配置权重本身不改**；factor_results 同时回显原 weight 与 weightUsed。

## 7. 四类验证案例（seed.sql 固定演示员工 E1001–E1004，AFTER_DEPT 口径）

## 8. 人工确认与调整的留痕设计

1. **建议与结论分表**：快照（`perf_recommendation_snapshot`，只增）与结论（`perf_manual_conclusion`，当前一行）通过 snapshot_id 关联；终审动作要求结论行必须存在（03 §1.3 FINAL_APPROVE 前置③）。
2. 两种作结论方式：
   - `ADOPT_CONCLUSION`：完全采纳，is_adjusted=0，但 `ackManual=true` 时表示"知悉需人工确认仍按建议执行"；
   - `ADJUST_CONCLUSION`：改 final_score/final_grade，engine_score/engine_grade 永远保留快照原值；理由 ≥10 字；分与档不一致需 ackMismatch；CAS 更新 version。
3. 每次作出/修改写 `perf_conclusion_history`（CREATE/MODIFY/OVERRIDE + before/after JSON）+ `sys_operation_log`（动作、前后快照）；申诉成立改判走 MODIFY。
4. 调整理由必须结构化可选标签（数据补录/评价偏差/特殊贡献/违纪加减/其他）+ 文本，供答辩统计"AI 建议采纳率"（`agent_call_log.adopted` 与 conclusion.is_adjusted 交叉出图，演示口径）。
5. 禁止性规则：无快照不得作结论；员工/主管角色不得改结论；不得以 Agent 对话文本作为改分依据（依据只认 snapshot.evidence_list 与制度条款 chunk 出处）。
